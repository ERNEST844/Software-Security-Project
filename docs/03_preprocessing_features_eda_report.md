Everything here is regenerated by the scripts in `src/` (run order in `README.md`). Numbers come from `results/eda_summary.json`, `results/project_summary_t0.csv`, `results/leakage_checks.json` and `results/matcher_validation_npm.json`.

## 2. Feature rationale

| Feature group | Features | Why (evidence) |
|---|---|---|
| Severity | `cvss_base`, `sev_rank`, vector components (AV, AC, PR, UI, SC, C, I, A) | Standard severity descriptors; the baseline's signal and the thing to beat (L03, L04). |
| Advisory descriptors | `cwe_primary`, `n_advisories`, `n_affected_packages`, `n_ecosystems`, `has_fix`, ecosystem flags | Weakness class and breadth plausibly relate to exploitability; cheap and available at disclosure. |
| Age | `advisory_age_days` | Exploitation evidence accrues with time since disclosure; also controls right-censoring. |
| Exploitation evidence | `poc_count_at_T`, `epss_at_T`, `epss_pct_at_T` | Direct evidence of attacker interest (L03, L04). EPSS pending. |
| Graph position (project level) | `is_direct`, `depth`, `fan_in`, `fan_out`, `pagerank`, `ancestors`, `descendants` | Exposure and blast radius propagate through the dependency structure (L07, L08, L09). |
| Package health (project level) | `pkg_age_days`, `days_since_last_release`, `releases_prior_12m`, `installed_version_age_days`, `version_lag_days` | Abandoned or lagging packages are harder to fix and more likely to stay vulnerable; computed from immutable release dates, so valid as-of T. |

**Deliberately excluded:** advisory reference counts and reference types (FIX/REPORT/EVIDENCE), PoC star counts, package deprecation flags and current download counts. These are current values or accrue over time and would leak post-T information.

## 3. Leakage checks (all pass)
C1 published ≤ T for every row; C2 no label window beyond the cut-off; C3 no duplicate CVE per cohort; C4/C5 candidates exclude already-positive CVEs; C6/C7 positives lie strictly inside (T, T+12m]; C8 development windows end on/before the test snapshot (2025-10-08); C9 feature list contains no label-derived column; C10 `poc_count_at_T` independently recomputed from the raw files for 200 rows (0 mismatches); C11 45 of 307 package-version-CVE triples occur in more than one project, so project-level splits must be **by project**; C12/C13 project findings use only advisories published ≤ T0 and releases ≤ T0.
Residual risks that cannot be tested are listed in `results/leakage_checks.json` and in protocol §8.

## 4. Data quality

**SBOMs.** 15 CycloneDX SBOMs, 23,827 components in total, every dependency edge points to a known component, and the one or two components per SBOM without a package URL (metadata entries) are skipped. Syft reads package-lock.json, yarn.lock, pnpm-lock.yaml, uv.lock and poetry.lock. Graph limitation: "direct" is the set of components with no incoming edge; in monorepos this includes workspace-level dependencies.

**Matcher validation against an independent source.** 1,279 package-version pairs (579 flagged by us + 700 random unflagged) were checked against npm's own audit endpoint. Recall 100% (npm found nothing we missed); precision 99.5% (11 of 2,088 advisory matches were ours only). Inspection of the cases: webpack-dev-middleware 7.4.5 and devalue are affected by advisories only 2 weeks old that npm's service had not yet ingested; multer 1.4.4-lts.1 is a prerelease-labelled version that npm's range logic excludes but the advisory's range (introduced 0, fixed 2.0.0) includes. These are not matcher errors. PyPI has no equivalent independent check yet (stated limitation). Unit tests of the version-range logic: 9/9 pass; 33 version comparisons (23 PyPI, 10 npm) involved unparsable version strings and were skipped.

**Vulnerability records.** 35,568 non-withdrawn advisories; 1,212 withdrawn were dropped; 3,632 have no CVE (cannot be linked to KEV, PoC or EPSS, so excluded from the population dataset); 31,936 unique CVEs. CVSS missing for 6.7% of 2025-cohort CVEs (8.2% across all rows); 2.2% have only a CVSS v4 vector (components mapped); `cwe_primary` missing for 3.2%. All dated fields are complete.

## 5. Exploratory results — project level (snapshot 2025-10-08)

- **23,827 components, 267 of them vulnerable (1.1%)**, giving **374 findings** (357 with a CVE, 17 without). Severity (GitHub label): Moderate 170, High 94, Low 74, Critical 36.
- **93.9% of findings are in transitive dependencies** (91.7% at depth > 1; the 23 direct findings are 6.1%). Scanners that only look at declared dependencies would miss almost everything.
- **Technical lag is large:** median installed-version age 738 days; median lag to the newest release 630 days; median advisory age at T 211 days (many findings were fixable for months).
- Findings per project range from 0 (etherpad-lite) to 100 (cal.com); full table in `results/project_summary_t0.csv`.
- For context: if the same 2025 lockfiles were scanned today with today's advisories, the count would be **5,016** (not 374). This is a contrast of snapshot time, not a trend claim: it shows how quickly disclosed advisories accumulate against pinned versions.
- Labelled positives among project findings: 1 KEV-positive, 12 PoC-positive (of 357 / 318 candidates).
- Student-owned project: 15 components, 0 known vulnerabilities on 2026-10-13.
